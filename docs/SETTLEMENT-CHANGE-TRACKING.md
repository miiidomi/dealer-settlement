# 지급완료 정산 변경 확인

관리자가 월별 정산 정보에서 **지급완료**를 저장하면 서버가 해당 월의 정산 금액과 계산에 사용한 상세 내역을 함께 보관합니다. 할부구매 입금분의 정산월을 먼저 반영하여 지급 처리 직후 비교 금액이 달라지지 않도록 합니다.

그 뒤 원가·납입·배분율·선지급 등 정산 내역이 달라지면 해당 월에 **지급완료 · 재확인 필요**가 표시됩니다. 선택 기간 밖의 변경 월도 화면 상단에 표시됩니다. **변경 상세**에서 저장 금액, 현재 금액, VAT 포함 최종 차액과 가맹점·항목별 변경을 확인할 수 있습니다. 금액이 서로 상쇄되어 총액이 같아도 계산 내역의 변경은 표시합니다.

관리자가 **변경 확인 완료**를 누르면 현재 변경 알림을 해제합니다. 최초 지급 시점 금액은 계속 보관하며, 새 변경 또는 마지막 확인 이후의 원복도 다시 표시합니다. 확인 처리는 추가 지급이나 회수가 이루어졌다는 뜻은 아닙니다. 정산일자·메모만 바꾸면 기존 저장 금액을 덮어쓰지 않습니다. 지급완료를 취소하고 다시 완료하면 새 지급 기준을 저장합니다.

## 기존 지급완료 기록

이 기능 도입 전에 저장된 지급완료 기록에는 당시 금액이 없습니다. **기준금액 미등록**으로 표시하며, 관리자가 **현재 금액 기준 등록**을 실행하면 등록 시점부터 비교합니다. 이를 과거 실제 지급금액으로 해석하면 안 됩니다.

## DB 변경 및 설치

`drizzle/0022_normal_lyja.sql`은 `monthly_settlement_statuses`에 nullable TEXT 열 `paid_snapshot`, `reviewed_snapshot`을 추가하고 누락된 위약금 스키마를 보완합니다. 기존 기록을 삭제하거나 금액을 변경하지 않습니다. 신규 DB에는 전체 마이그레이션을 순서대로 적용합니다. 기존 DB는 실제 스키마와 적용 이력을 먼저 확인해 중복 ALTER를 방지해야 합니다. 원본 저장소에서 누락된 과거 청라 데이터 정리 SQL은 테스트 fixture로만 복원했으며 원격 D1에 적용하지 않습니다.

사용자 요청에 따라 GitHub에는 새 DB 마이그레이션 및 메타데이터를 올리지 않습니다. 별도로 제공하는 마이그레이션 ZIP 또는 전체 코드 ZIP에서 가져와 적용하세요. `db/schema.ts`는 앱 코드와 함께 업데이트됩니다.

## 검증

실제 DB 데이터를 복제한 로컬 DB에 스키마 변경을 적용하여 레코드 보존을 확인합니다. 합성 테스트 데이터로 지급 저장, 원가 수정, 기존 기준 보존, 변경 확인, 권한 제한, 동시 수정 거부, 할부구매 정산월 기록, 동일 총액의 상세 변경 및 재변경을 검증합니다.
