# MCP 전체 업무 정보 조회 v1.2.0 (2026-10-12)

운영 DB의 업무 테이블 19종을 대조해 저장된 모든 업무 자료의 읽기 전용 조회를 제공한다. 내부 마이그레이션 관리 테이블과 인증 비밀값은 업무 자료가 아니다.

get_records는 dealer를 생략하면 모든 딜러의 자료를 조회한다. dealer를 지정하면 해당 딜러로 제한한다. products와 costs는 공통 자료이므로 dealer 지정 여부와 관계없이 공통 목록이다. section에 해당할 때 merchantId와 productId 필터를 사용할 수 있으며 지원하지 않는 필터는 오류로 알린다.

모든 목록은 offset/limit 페이지 방식이다. nextOffset이 null일 때까지 이어 조회해야 전체 결과다. get_records 금액은 DB 원본값이다. Salesforce CMS 월청구액 원본은 VAT 포함일 수 있다. 명의변경 제품에 저장 원가가 남아 있어도 실제 적용 원가는 0이다. 공급가액 정규화 및 최신 유효 원가는 get_merchant_details로 확인하고, 정산금액은 get_settlement/explain_settlement를 사용한다.

## 추가 도구

- find_merchants: ownershipTransfer=Y/N으로 명의변경 가맹점 조회. 유효 Y 설치제품이 하나라도 있으면 가맹점을 Y로 표시. 수동 명의변경 설정을 우선 적용하며 기존 자산의 '명변됨'과는 별개이다.
- get_merchant_details: 가맹점 전체 설치제품·명의변경·자산 상태·유효 원가, 납부자·납입·청구·위약금 상세를 기간 제한 없이 페이지 조회.
- get_settlement_snapshot: dealer, month, kind=paid 또는 reviewed로 지급/마지막 확인 당시 저장 산출내역·총액을 페이지 조회. 자료가 없으면 not_persisted. 형식 및 딜러·월을 검증하며 현재 금액으로 과거 자료를 만들지 않음.
- get_sync_status: 전체 또는 딜러별 가맹점·설치제품·위약금 레코드의 동기화 시각 관측 개수, 최초·최신 시각을 집계.
- get_data_coverage: 제공되는 전체 종류와 저장되지 않은 정보의 한계를 안내.

월별 지급 목록은 큰 산출내역 JSON을 직접 반복 반환하지 않고 유무를 표시한다. 산출내역 내용은 get_settlement_snapshot을 사용한다.

## 저장되지 않는 정보

| 항목 | 조회 가능한 대체 정보 | 한계 |
|---|---|---|
| Excel 미매칭·중복 행별 사유와 원본 행 번호 | 업로드 집계 및 정상 반영 납입 | 원본 Excel을 다시 확인해야 함 |
| 개별 Salesforce 자산 ID별 전체 변경 이력 | 설치제품의 집계 상태, 수동 설정, 원본 문의 연결 | 과거 자산 전환 이력을 MCP만으로 복원할 수 없음 |
| 동기화 실행별 성공·실패 로그 | 레코드별 시각과 get_sync_status 관측 집계 | 관측 최신 시각은 전체 동기화 성공을 보장하지 않음 |

세 항목은 get_data_coverage에서 not_persisted로 명시한다. 과거 상세자료를 복원하거나 새 이력을 저장하는 기능은 이번 읽기 전용 MCP 확장에 포함되지 않는다.

예시: '모든 딜러의 선지급 내역 보여줘', '이정수 원가 이력과 수당 규칙 전부 보여줘', '월별 지급 상태와 세금계산서 발행일 알려줘', '이정수 2026년 9월 지급 당시 산출내역 보여줘', '사용자별 역할과 연결 딜러 확인해줘'.

관리자 권한은 모든 호출마다 재검사한다. 업무 DB는 조회만 수행한다. 기존 MCP 주소·로그인 설정은 유지하며 이전 도구 목록이 남아 있으면 호스트의 MCP 도구 목록을 갱신해야 한다.
